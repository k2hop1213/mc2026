# 시험용 AI 프롬프트 템플릿 (UART 프로토콜)

## 시험 형태 (교수님 안내)

- 조교가 만든 **PC 쪽 UART 프로그램**을 설치한다. 시리얼 모니터 대신 이것을 쓴다.
- 그 프로그램에서 버튼/입력을 하면 **내 보드가 제어되도록** 아두이노 코드를 짠다.
  (보드 → 프로그램으로 값을 보내 표시하는 것도 나올 수 있다)
- 핵심은 **프로토콜** : 정해진 형식의 패킷을 **받아서 파싱**하고, 필요하면 **패킷으로 보낸다**.
- AI 가 도와줄 수는 있지만, 실제 바이트 형식과 보드 동작은 **직접 확인**해야 풀린다.
- 개인 노트북으로 보고 인터넷, AI 모두 사용 가능하다. 패킷 형식과 회로는 시험 때 달라질 수 있다.

## 시험장 순서

| 단계 | 할 일 | 쓰는 것 |
|---|---|---|
| 1 | 프로그램 설치, 보드레이트·패리티·정지 비트·포트 확인 | |
| 2 | 회로가 지정되어 있으면 배선, 그 뒤 `tool_hw_check` 로 부품 확인 | [F], `src/tools/hw_check` |
| 3 | `tool_byte_monitor` 업로드 → 프로그램 버튼을 하나씩 눌러 **실제 바이트** 적기 | [바이트 읽는 법](#바이트-읽는-법) |
| 4 | 문제지 설명 + 적은 바이트로 **패킷 형식 정리** | [G] |
| 5 | 틀 고르기 : Arduino 함수를 쓸 수 있으면 `exam_base`, Serial 없이 main() 과 레지스터로 쓰면 `exam_avr` | [틀 고르기와 설정](#틀-고르기와-설정) |
| 6 | **수신만** 먼저 : `DEBUG_LED = true` 로 패킷이 들어오는지 확인 | [A] 단계 1 |
| 7 | 명령별 **동작** 붙이기 | [A] 단계 2 |

## [G] 프로토콜 정리 프롬프트

```
아래는 시험에서 받은 PC 쪽 UART 프로그램과 문제 설명이야.
아직 코드는 쓰지 말고, 아두이노가 지켜야 할 통신 규칙만 정리해 줘.

[문제 설명]
(문제지에 있는 프로토콜/명령 설명 그대로)

[프로그램 정보]
- 보드레이트 / 데이터 비트 / 패리티 / 정지 비트 : (예: 9600, 8, N, 1)
- 버튼/입력과 실제로 온 바이트 (byte_monitor 로 확인, 16진수)
  (예: [LED ON] → 02 01 00 01 03,  [패턴 AA] → 02 02 01 AA AD 03,  [ADC 요청] → 02 41 00 41 03)
- 프로그램이 받는 쪽 화면 : (예: 받은 바이트를 16진수로 표시 / "ADC : 512" 표시 / 그래프 / 없음)
- 조교가 준 코드나 설명서 : (있으면 첨부)

출력 형식
1. 패킷 형식 표 : 칸 이름 | 크기(byte) | 값(16진수) | 2진값인지 ASCII 인지
2. 명령별 표 : 명령 바이트 | 데이터 칸 내용 | 아두이노가 할 동작 | 돌려보낼 응답 (바이트 그대로)
3. 길이(LEN) 칸이 있으면 무엇을 세는지 (데이터만? 명령 포함?)
4. 체크섬 칸이 있으면 계산 범위와 방법(합의 하위 8비트 / XOR / 2의 보수) + 내가 적은 바이트로 검산
5. 2바이트 이상 숫자가 있으면 바이트 순서 (상위 먼저? 하위 먼저?)
6. 아두이노 수신 FSM 상태 전이 표 : 지금 상태 | 받은 바이트 조건 | 할 일 | 다음 상태
7. 문제 설명과 실제 바이트가 다르거나 애매한 점 (조교에게 물어볼 것)
```

### 바이트 읽는 법

`tool_byte_monitor` 는 받은 바이트를 LED 에 하나씩 0.6초씩 띄운다. (D2 = bit0, 오른쪽이 bit0)
프로그램에 받은 글자 창이 있으면 `RX 02 31 03` 처럼 16진수로도 보인다.

| LED (D9 ← D2) | 16진수 | 의미 |
|---|---|---|
| 0000 0010 | 0x02 | STX (2진값) |
| 0000 0011 | 0x03 | ETX (2진값) |
| 0011 1100 / 0011 1110 | 0x3C / 0x3E | 문자 `<` / `>` |
| 0011 0001 | 0x31 | **문자** `'1'` |
| 0000 0001 | 0x01 | **숫자** 1 |
| 0100 0001 | 0x41 | 문자 `'A'` |
| 0000 1101 / 0000 1010 | 0x0D / 0x0A | `\r` / `\n` (줄 끝) |

- `'1'`(0x31) 과 `1`(0x01) 을 헷갈리면 명령이 안 먹는다. 실습 코드는 ASCII(`'<'`, `'1'`), 수업 자료는 2진값(0x02, 0x01) 이었다.
- 숫자 데이터가 `"512"`(문자 3개, `atoi`) 인지 `02 00`(값 2바이트, `(hi << 8) | lo`) 인지 확인한다.
- 버튼을 같은 것으로 두 번 눌러 바이트가 매번 같은지도 본다. (순번/카운터 칸이 있을 수 있다)

### AI 답 확인용 : 파서 기본 골격

AI 코드가 이 모양에서 크게 벗어나면 의심한다. (칸 구성·체크섬 방식은 문제에 맞춰 바뀐다)

```
패킷 예 : | STX 0x02 | CMD | LEN | DATA × LEN | SUM | ETX 0x03 |     SUM = (CMD + LEN + DATA...) 의 하위 8비트
```

```cpp
const byte STX = 0x02;
const byte ETX = 0x03;
const int MAX_DATA = 16;

enum { WAIT_STX, GET_CMD, GET_LEN, GET_DATA, GET_SUM, WAIT_ETX };
byte state = WAIT_STX;

byte cmd = 0;
byte len = 0;
byte idx = 0;
byte sum = 0;
byte data[MAX_DATA];
bool ready = false;
unsigned long last_rx = 0;

void rx_decode() {
  // 패킷 도중 100ms 동안 아무것도 안 오면 처음부터
  if (state != WAIT_STX && millis() - last_rx > 100) {
    state = WAIT_STX;
  }

  while (Serial.available() > 0 && !ready) {
    byte c = Serial.read();
    last_rx = millis();

    switch (state) {
    case WAIT_STX: // STX 가 아니면 무시
      if (c == STX) { state = GET_CMD; }
      break;
    case GET_CMD:
      cmd = c;
      sum = c;
      state = GET_LEN;
      break;
    case GET_LEN:
      len = c;
      sum += c;
      idx = 0;
      if (len > MAX_DATA) { state = WAIT_STX; } // 너무 길다 → 버림
      else if (len == 0) { state = GET_SUM; }
      else { state = GET_DATA; }
      break;
    case GET_DATA:
      data[idx++] = c;
      sum += c;
      if (idx == len) { state = GET_SUM; }
      break;
    case GET_SUM: // 체크섬이 틀리면 버림
      state = (c == sum) ? WAIT_ETX : WAIT_STX;
      break;
    case WAIT_ETX:
      if (c == ETX) { ready = true; } // 완성
      state = WAIT_STX;                // 맞든 틀리든 처음으로
      break;
    }
  }
}

void send_packet(byte c, const byte* d, byte n) {
  byte s = c + n;
  Serial.write(STX);
  Serial.write(c);
  Serial.write(n);
  for (byte i = 0; i < n; i++) {
    Serial.write(d[i]);
    s += d[i];
  }
  Serial.write(s);
  Serial.write(ETX);
}

void loop() {
  rx_decode();
  if (ready) {
    run_command(cmd, data, len); // 명령별 동작 + 응답
    ready = false;
  }
}
```

볼 곳
- 상태마다 **오류면 WAIT_STX 로 돌아가는 길**이 있는가
- `data[idx++]` 전에 **LEN 을 버퍼 크기와 비교**하는가 (안 하면 메모리를 덮어쓴다)
- 체크섬 범위가 [G] 에서 정리한 것과 같은가
- 실행이 끝나면 `ready = false` 로 되돌리는가 (안 하면 같은 명령이 계속 실행되거나, 두 번째부터 안 받음)
- 2바이트 값 : `int v = (data[0] << 8) | data[1];` (상위 먼저일 때), 보낼 때 `v >> 8`, `v & 0xFF`

## [F] 회로 설계 프롬프트 (회로를 더 꾸며야 할 때)

```
너는 Arduino Uno(ATmega328P, 16MHz, 5V) 실습 조교야.
아래 [문제]를 풀기 위한 회로를 브레드보드에 추가해야 해.

[가진 부품]
(예: LED 8개, 220Ω 저항 여러 개, 택트 스위치 3개, 피에조 부저 1개,
     10kΩ 가변저항 1개, GL5528 조도센서 1개, 10kΩ 저항 1개, 점퍼선, 브레드보드)

[이미 꽂혀 있는 회로]
LED D2 ~ D9 Active Low, 스위치 D10 ~ D12 + PCINT0, 가변저항 A1, 조도센서 A3, 부저 A0

[문제]
(시험 문제 그대로)

규칙
1. D0, D1 은 UART 용이라 쓰지 않는다.
2. 스위치는 INPUT_PULLUP, 핀 - 스위치 - GND (누르면 LOW). 인터럽트가 필요하면 어떤 벡터를 쓰게 되는지 고려한다.
3. LED 는 저항(220~330Ω)과 직렬, Active High/Low 를 명시한다.
4. 아날로그 센서는 A0 ~ A5. 저항형 센서는 고정 저항과 전압 분배로 연결한다.
5. 모든 GND 는 아두이노 GND 와 공통. 브레드보드 위 레일은 GND 만, 아래 레일은 +5V 만 쓴다.
6. [이미 꽂혀 있는 회로]는 그대로 두고 추가할 배선만 알려 준다.

출력 형식
- 핀 배치 표 : 부품 | 아두이노 핀 | 포트/비트 | 인터럽트 | 연결 방법
- 배선 순서와 실수하기 쉬운 곳
- [A] 의 [회로 정보]에 바로 붙여 넣을 형태
- 배선도 : 전체 회로(기존 + 추가)를 기호 회로도가 아니라 **실제 부품 모양의 브레드보드 배선도**로,
  SVG 파일 하나에 그린다. 첨부한 breadboard.svg 와 같은 모양으로.
  · 흰 배경, viewBox 사용, 글꼴은 'Malgun Gothic', Arial. 위쪽에 제목 한 줄 + 설명 한 줄
  · 위에 풀사이즈 브레드보드(63열, a ~ j, 가운데 홈, 위아래 전원 레일), 아래에 Arduino UNO R3
  · 브레드보드 : 연한 회색 판, 구멍은 2.54mm 간격(15px)의 작은 사각형, 열 번호(1, 5, 10 ...)와 행 글자(a ~ j)
  · UNO : 청록색 기판, 왼쪽에 USB·전원잭, ATmega328P 칩, 실제 위치의 검은 핀 헤더
    위쪽 헤더 왼→오 : SCL, SDA, AREF, GND, 13, 12, ~11, ~10, ~9, 8, (간격) 7, ~6, ~5, 4, ~3, 2, TX→1, RX←0
    아래쪽 헤더 왼→오 : IOREF, RESET, 3.3V, 5V, GND, GND, VIN, (간격) A0 ~ A5
    핀 이름은 실제 보드처럼 헤더 옆에 세로 흰 글씨
  · 전원 레일 규칙 (꼭 지킨다)
    - **아래 레일은 +5V 만** 쓴다. 안쪽 줄(j줄 바로 아래, 빨간 선)이 +, 아두이노 5V 를 여기에 꽂는다.
    - **위 레일은 GND 만** 쓴다. 바깥쪽 줄(맨 위, 파란 선)이 −, 아두이노 GND 를 여기에 꽂는다.
    - 위 + 줄과 아래 − 줄은 비워 둔다. 레일끼리 잇는 점퍼도 쓰지 않는다.
    - +가 필요한 부품은 브레드보드 아래쪽(f ~ j)에서 아래 + 레일로,
      GND 가 필요한 부품은 위쪽(a ~ e)에서 위 − 레일로 잇는다. 필요하면 가운데 홈을 건너 꽂는다.
  · 부품은 실제 모양 : 저항 = 베이지 몸통 + 색띠(220Ω 빨-빨-갈, 10kΩ 갈-검-주), LED = 빨간 원 + 다리 2개
    (긴 다리(+) 쪽 표시), 택트 스위치 = 회색 사각형 + 검은 버튼(가운데 홈을 걸쳐 꽂음),
    가변저항 = 몸통 + 손잡이 + 다리 3개, 조도센서 = 주황빛 원판 + 지그재그 무늬 + 다리 2개
  · LED 는 왼쪽부터 D9 ... D2 (오른쪽이 D2 = 최하위 비트)
  · 선 색 : 5V 빨강, GND 검정, LED 핀 노랑, 스위치 핀 파랑, 아날로그 입력은 핀마다 다른 색(A1 주황, A3 초록 ...)
    선은 두꺼운 색 선 + 어두운 테두리, 양 끝은 구멍/핀에 꽂힌 점으로. 선끼리 **교차하지 않게** 경로를 잡는다.
  · 보드 → UNO 선마다 이름표(D9, A3, 5V, GND ...)를 단다.
  · 부품 이름표(이름 + 연결 설명)는 빈 구멍 위에 흰 상자로, 이번에 새로 추가한 부품은 주황 점선 상자로 묶는다.
  · 오른쪽 아래에 "선 색깔" 범례와 "체크"(실수하기 쉬운 곳) 상자
```

### Uno 핀 기초

| 핀 | 특징 |
|---|---|
| D0, D1 | UART RX/TX. 연결하면 업로드·통신이 망가짐 |
| D2, D3 | INT0, INT1 |
| D8 ~ D13 | PORTB (PB0 ~ PB5), `PCINT0_vect`, PCIE0, PCMSK0 |
| A0 ~ A5 (= D14 ~ D19) | PORTC (PC0 ~ PC5), `PCINT1_vect`, PCIE1, PCMSK1, 아날로그 입력 |
| D0 ~ D7 | PORTD (PD0 ~ PD7), `PCINT2_vect`, PCIE2, PCMSK2 |
| D3, 5, 6, 9, 10, 11 | PWM (`analogWrite`). D5, D6 은 Timer0 (millis 와 같은 타이머) |
| D13 | 보드 LED 가 붙어 있음 |

```
LED (Active High)  : 핀 ── 220Ω ── LED(+) ── LED(-) ── GND          핀 HIGH = 켜짐
LED (Active Low)   : 5V ── 220Ω ── LED(+) ── LED(-) ── 핀           핀 LOW  = 켜짐
스위치 (풀업)       : 핀 ── 스위치 ── GND, INPUT_PULLUP                누르면 LOW
가변저항           : 양 끝 다리 ── 5V / GND, 가운데 다리 ── A핀
조도센서 (GL5528)  : 5V ── GL5528 ── A핀 ── 10kΩ ── GND              밝을수록 값이 큼
```

```
위 코드를 보드에 올렸는데 기대와 다르게 동작해.

- 한 일 : (예: 프로그램의 [LED ON] 버튼을 눌렀다)
- 프로그램이 보낸 바이트 : (byte_monitor 나 프로그램 로그로 본 값, 예: 02 01 00 01 03)

- 실제 : (예: 무반응 / 처음 한 번만 됨 / 응답이 프로그램에 안 뜸 / LED 0x81 오류 표시)
- 프로그램 화면 : (응답이 어떻게 보이는지 그대로)
- 빌드 오류 : (있으면 그대로)

[프로토콜]과 [규칙]을 기준으로 원인 후보를 가능성 높은 순서로 3개 이내로 말해 줘.
FSM 의 몇 번째 상태에서 막히는지 위 바이트를 한 바이트씩 따라가며 확인해 줘.
코드 문제면 고친 함수만, 배선 문제면 확인 방법을 줘.
```

### 어디서 막혔는지 가르기

- **수신 확인** : `DEBUG_LED = true` 로 올린다. 완성 패킷 → LED 에 CMD, 오류 → `0x80 | 오류 번호`.
  - LED 무반응 → STX 를 못 찾음 (값/보드레이트/포트 연결)
  - 0x81 ~ 0x87 → 오류 번호로 칸을 찾는다 (1 LEN, 2 ETX, 3 SUM, 4 시간 초과, 5 명령, 6 LEN 불일치, 7 채널)
- **응답 확인** : 응답 대신 LED 로 보낼 바이트를 띄워 보거나, 프로그램의 수신 로그를 본다.

| 증상 | 먼저 의심할 것 |
|---|---|
| 업로드 실패 | **조교 프로그램/시리얼 모니터가 포트를 잡고 있음** → 연결 해제 후 업로드, D0/D1 에 뭔가 연결됨 |
| 업로드 후 프로그램 버튼 무반응 | 프로그램에서 포트 다시 연결 안 함, 보드레이트 |
| 패킷이 전혀 안 잡힘 | STX 값(`0x02` vs `'<'`), 문자 `'1'` 과 값 `0x01` 혼동 |
| 항상 오류 표시 | LEN 이 무엇을 세는지, 체크섬 범위/방식, 줄 끝 `\r\n` 이 더 붙어 옴 |
| 처음 한 번만 됨 | `ready` / `state` 초기화 안 함 |
| 명령이 늦게/몰아서 실행됨 | 동작 안의 긴 delay 동안 패킷이 쌓임 |
| 프로그램이 응답을 못 알아봄 | 디버그 출력이 섞임, 응답 체크섬/LEN, 숫자를 문자로 보냈는지 값으로 보냈는지 |
| 2바이트 값이 엉뚱함 | 바이트 순서(상위/하위) 반대 |
| `multiple definition of __vector_18` | Arduino Serial 을 쓰면서 `ISR(USART_RX_vect)` 직접 정의. `base_avr` 는 Arduino 코어와 같이 빌드하지 않는다 |
| LED 가 반대로 켜짐 | Active High/Low 와 `led_write` 반전 불일치 |

& "$env:USERPROFILE\.platformio\penv\Scripts\python.exe" scripts/packet_tool.py        # 포트 목록

02 31 03      16진수 그대로 보내기
t <13>        글자 그대로 보내기

pb 01 AA      체크섬을 일부러 틀리게 보내기
q             끝내기 (업로드 전에 꼭 끝낸다)

1. 3주차 [05_protocol](../src/w03_uart/05_protocol/main.cpp) 의 STX/ETX 를 `'<' '>'` → `0x02 0x03` 으로 바꾸기
2. LEN 칸 추가 : `STX | CMD | LEN | DATA × LEN | ETX`
3. 체크섬 추가, 틀린 패킷 버리기
4. 응답 패킷 : 명령을 받으면 `STX | CMD+0x80 | 0 | SUM | ETX` 로 확인 응답
5. 값 응답 : 요청을 받으면 ADC 값을 2바이트로 응답
6. 보드 → PC : 스위치를 누르면 패킷 보내기
7. 잘린 패킷 / 쓰레기 바이트 / 연속 패킷에도 멀쩡한지 확인

## 틀 고르기와 설정

| 시험 환경 | 쓰는 틀 | 빌드 |
|---|---|---|
| `Serial`, `setup()`, `loop()` 사용 가능 | `src/exam/base/main.cpp` | `exam_base` |
| `Serial` 없이 `main()` 과 레지스터 사용 | `src/exam/base_avr/main.c` | `exam_avr` |

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e exam_base -t upload --upload-port COM5
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e exam_avr -t upload --upload-port COM5
```

- `base_avr` 는 Arduino IDE 에서 쓰지 않는다. 타이머 인터럽트가 Arduino 코어와 충돌한다.
- `base_avr` 의 부저는 123Hz 미만이면 소리가 나지 않는다. 나머지 패킷, 명령, 응답은 두 틀이 같다.

| 상수 | 값 | 쓸 때 |
|---|---|---|
| `DEBUG_LED` | `true` | LED 에 받은 CMD, 오류는 `0x80 \| 오류 번호` 를 표시한다. 일반 LED 동작은 안 나온다. UART 는 그대로다 |
| `SEND_ACK` | `false` | 문제에 성공 응답이 없을 때 |
| `SEND_ERROR` | `false` | 문제에 오류 응답이 없을 때. 패킷은 똑같이 버린다 |

| 바꿀 설정 | 고칠 곳 |
|---|---|
| 보드레이트 | `BAUD` (두 틀, `byte_monitor`, `byte_recorder`) |
| 패리티, 정지 비트 (Arduino) | `SERIAL_FRAME` (`base/main.cpp`, `byte_monitor`, `byte_recorder`) |
| 패리티, 정지 비트 (레지스터) | `UART_PARITY`, `UART_STOP_BITS` (`base_avr/main.c`) |
| PC 쪽 스크립트 | `stress_test.py`, `exam_base_test.py`, `read_log.py` 의 `--baud`. 이 스크립트들은 8N1 만 쓴다 |

## 프로그램이 포트를 잡고 있어서 바이트를 못 볼 때

`tool_byte_recorder` 는 받은 바이트를 EEPROM 에 저장한다. 프로그램을 끊은 뒤 읽을 수 있다. 프로그램의 보드레이트가 9600 이 아니면 코드의 `BAUD` 와 `--baud` 를 맞춘다. 패리티가 있으면 `read_log.py` 로 읽을 수 없다.

1. `& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e tool_byte_recorder -t upload --upload-port COM5`
2. `& "$env:USERPROFILE\.platformio\penv\Scripts\python.exe" scripts/read_log.py COM5 --clear`
3. 조교 프로그램을 연결하고 버튼을 하나씩, 1초씩 간격을 두고 누른다
4. 조교 프로그램 연결을 끊는다
5. `& "$env:USERPROFILE\.platformio\penv\Scripts\python.exe" scripts/read_log.py COM5` (버튼마다 한 줄씩 나온다)

프로그램 화면은 스크린샷으로, 보드 동작은 말이나 사진으로 AI 에게 전달한다.
